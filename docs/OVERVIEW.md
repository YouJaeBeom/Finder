# Paper Digest — 연구실 논문 모니터링 자동화

> 매월 1일 아침, 지난 60일간 상위 학회·저널에 나온 논문 중 **연구실 구성원 각자의 주제에 맞는 것**을 골라 한국어 노트로 정리해 Notion에 쌓아주는 도구입니다.
> 코드: `github.com/YouJaeBeom/Finder` · 문서 작성 2026-08-20

---

## 1. 무엇을 해결하나

상위 학회·저널을 따라 읽는 일은 개인이 매달 반복하는 작업이지만, 그 과정 대부분은 사람마다 다르지 않습니다.

| 단계 | 사람이 매달 하는 일 | 이 도구가 하는 일 |
|---|---|---|
| 어디를 볼지 정한다 | ACL·SIGIR·CHI·TPAMI … 목록을 기억해서 하나씩 확인 | 학회 238곳 + 저널 28곳을 매달 자동 조회 |
| 새로 나온 것을 추린다 | 프로시딩이 언제 올라오는지 눈치껏 확인 | 게재일 기준 60일 창을 매달 다시 훑고 중복 제거 |
| 내 주제인지 판단한다 | 제목과 초록을 눈으로 훑음 | 검색식 1차 필터 → LLM이 0~10점으로 관련도 채점 |
| 읽을 만한 것을 정리한다 | 메모를 따로 남기거나 남기지 않음 | 한국어 4단락 노트를 자동 작성해 Notion에 축적 |

핵심은 **"상위 학회·저널 풀에서 내 연구에 맞는 것을 찾는다"** 이지, "더 급이 높은 학회를 찾는다"가 아닙니다. venue 등급으로는 아무것도 거르지 않고, 무엇을 볼지는 관련도가 정합니다.

## 2. 결과물

Notion 워크스페이스에 이런 구조가 **코드에 의해** 만들어집니다. 사람이 Notion에서 손으로 만드는 것은 맨 위 빈 페이지 하나뿐입니다.

```
📄 연구 다이제스트                (사람이 만드는 유일한 페이지)
├── 📰 IT 뉴스                   공용 DB — 전원 공유, 실행당 1회
├── 📄 유재범                    멤버 페이지 (자동 생성)
│   └── 📚 논문                  그 사람 전용 DB (자동 생성)
├── 📄 김민수
│   └── 📚 논문
└── ...
```

**논문 DB의 각 행**은 하나의 논문이고, 컬럼은 `Title · Venue · Score(관련도 0~10) · Kind · Status · Published · Tags · URL · Collected` 입니다. 점수순·학회순·날짜순 정렬과 필터는 Notion 기본 기능으로 각자 씁니다.

**행을 열면** 한국어 노트가 있습니다.

```
📊 관련도 점수: 8/10
🔗 https://doi.org/...

한 줄 요약        이 논문이 무엇을 했는지 한 문장
핵심 기여         1. … 2. … 3. …
방법             어떤 방식으로 했는지
내 연구와의 연결점   이 사람의 research_profile 에 비추어 왜 볼 만한지
```

마지막 단락이 이 도구의 특징입니다. 같은 논문이 두 사람에게 걸리면 **각자의 연구 소개에 맞춰 서로 다른 연결점**이 쓰입니다. 실행 로그에는 "이번 달 두 명 이상이 받은 논문" 목록도 남아서, 연구실 안에서 겹치는 관심사를 볼 수 있습니다.

뉴스는 Hacker News(100점 이상)와 직접 고른 RSS 피드에서 모아 출처별로 번갈아 상위 20건을 공용 DB에 씁니다. 뉴스에는 관련도 채점을 하지 않습니다 — 소스가 이미 큐레이션돼 있어서 모델을 한 번 더 부르는 값만큼의 이득이 없습니다.

## 3. 어떻게 고르나 — 3단 필터

```
285곳 학회·저널 (60일) ──▶ 약 2,100편 ──▶ [1] 검색식  ──▶ 약 500편
                                          ──▶ [2] 이미 받은 것 제외
                                          ──▶ [3] LLM 관련도 채점 (0~10)
                                                     └─ 5점 이상만 노트 작성 ──▶ 월 20~40편
```

**[0] venue 화이트리스트가 품질 장치의 전부입니다.** 목록(`venues.csv`, 285곳 중 Semantic Scholar에 논문이 있는 266곳)에 있는 곳의 논문만 들어옵니다. 주제 필터로 대신하려던 초기 설계는 실패했습니다 — OpenAlex를 쓰던 시절, 통과 논문 1위 venue가 NLP 논문을 싣는 약탈적 저널(*Advanced Electromagnetics*)이었습니다. 목록은 한국정보과학회·BK21·KAIST·SNU·POSTECH 종합 순위를 정규화한 표에 FAccT·AIES·ECIR을 손으로 더한 것입니다.

**[1] 검색식(query)은 비용을 줄이기 위한 느슨한 1차 필터입니다.** 논문 데이터베이스에서 쓰는 검색식 그대로이고, 구성원이 각자 한 번 작성합니다.

```
"political bias" OR stereotype OR sycophancy
OR ( (LLM OR "large language model") AND (bias OR fairness OR evaluation) )
```

**[2] 이미 받은 논문은 다시 오지 않습니다.** 판단 기준은 그 사람의 Notion DB 자체입니다 — 상태 파일이 아니라 결과물이 진실이므로, 상태 파일이 유실돼도 중복 페이지가 생기지 않습니다.

**[3] 관련도 채점에는 venue가 들어가지 않습니다.** 모델이 보는 것은 제목·초록과 그 사람의 연구 소개뿐입니다. 그래서 학회 목록을 넓혀도 관련 없는 분야는 5점 미만으로 떨어질 뿐입니다.

## 4. 실제로 잘 고르는가 — 측정한 것

**1차 필터가 좋은 논문을 버리지 않는지.** 초기에 "정밀한" 키워드 규칙을 쓰자, 채점 모델이 8~9점을 줬을 논문이 잘려나갔습니다. 정보 검색 연구자에게서 *"Evaluation Validity in Information Retrieval"*(9점)이 사라졌는데, 초록에 "bias"도 "diversity"도 없다는 이유였습니다. **주제가 아니라 분야를 잡도록** 바꾸자 그 6편이 전부 돌아오면서도 풀의 70~77%가 걸러졌습니다.

| 멤버 | 풀 | 1차 필터 통과 | 최종(5점 이상) |
|---|---:|---:|---:|
| 유재범 (LLM 정치 편향) | 2,088편 | 476편 (22.9%) | 26편 |
| 샘플-검색RAG | 2,088편 | 623편 (29.8%) | 120편 |
| 샘플-웹데이터 | 2,088편 | 582편 (28.0%) | 33편 |

*2026-08-19 실행 기준. 논문 179편 + 뉴스 20건 = 199페이지가 그날 만들어졌습니다.*

검색 분야에서 120편이 나온 것은 그 사람의 관심사가 학회 트랙 하나를 통째로 덮기 때문이고, 이런 경우는 개인이 자기 파일에서 컷오프를 올려 조절합니다.

**조용히 실패하지 않는지.** 이 종류의 도구에서 가장 위험한 실패는 "그럴듯한데 틀린 결과"입니다. 아무도 다시 확인하지 않기 때문입니다. 그래서 다음을 전부 실행 중단이나 오류 보고로 처리합니다: 못 읽는 검색식, 배제 조건만 있는 검색식, 후보는 있는데 한 편도 채점되지 않은 상태, 예산 상한 초과, 두 사람이 같은 표시 이름을 쓰는 경우. 테스트 443개가 push마다 돌고, 구성원 YAML 파일 검증도 CI에 포함돼 있습니다.

## 5. 비용과 운영 부담

| 항목 | 값 |
|---|---|
| 실행 주기 | 매월 1일 09:00(KST), GitHub Actions |
| 1회 실행 시간 | 3명 기준 약 11분 (병렬 12) |
| 모델 비용 | **10명 기준 월 약 $6** (채점 $3.2 + 노트 $2.9 + 뉴스 $0.2) |
| 그 외 비용 | 없음 — Semantic Scholar는 API 키 불필요, GitHub Actions 공개 저장소 무료 |
| 사람이 하는 일 | 구성원 등록 시 YAML 파일 1개 추가 (그 후로는 없음) |

지출은 코드가 막습니다. 인원 상한 15명, 1인당 상한 30편, 실행당 노트 600편을 넘으면 **경고가 아니라 실행 거부**입니다. 공용 API 키를 쓰므로 한 사람의 오타가 전원의 비용이 되기 때문입니다.

## 6. 지금 상태와 한계

**동작 중입니다.** 2026년 8월 기준 3명(본인 + 샘플 2명분의 가상 프로필)으로 매월 실행되고 있습니다. 가장 최근 실행에서 199페이지가 만들어졌고, 실패한 멤버는 없었습니다.

정직하게 적어둘 한계:

- **venue 목록 밖은 누구에게도 들어오지 않습니다.** 새 구성원의 분야가 목록에 없으면 프로필을 아무리 잘 써도 0건입니다. 그때는 `venues.csv`에 추가하는 것이 답이고, 이건 연구실 공용 결정입니다.
- **arXiv 프리프린트는 제외했습니다.** 하루 수백 편 대 학회 연 1회라, 켜두면 정리 대상이 사실상 전부 프리프린트가 됩니다. 최신성보다 심사를 거친 논문을 택한 결정입니다.
- **1차 필터에서 놓친 논문은 아무도 다시 보지 않습니다.** 그래서 "애매하면 넣는다"가 문서화된 원칙입니다.
- **사람당 연구 주제는 1개입니다.** 한 사람이 두 주제를 따로 받는 형태는 필요해지면 그때 붙일 여지를 남겨두고 미뤘습니다.
- **최종 판단은 사람이 합니다.** 5점 컷은 "읽어볼 가치가 있는지"의 1차 선별이지 논문의 가치 평가가 아닙니다.

## 7. 연구실에 도입한다면

구성원이 제출할 것은 **셋뿐**입니다. 나머지는 운영자가 파일 하나를 추가하면 됩니다.

1. **이름** — Notion 페이지 제목이 됩니다
2. **연구 소개 2~6문장** — 무엇을 연구하는지, 어떤 세부 주제에 관심 있는지, **관련도가 낮은 것은 무엇인지**까지. 이 글이 관련도 채점과 노트의 "내 연구와의 연결점"에 함께 쓰입니다
3. **1차 필터 검색식** — Scopus·Web of Science에서 쓰는 그 문법. 운영자가 대신 써주고 본인이 확인해도 됩니다

파일을 추가하고 push하면 다음 실행 때 그 사람의 Notion 페이지와 DB가 자동으로 생기고, 신규 인원은 지난 1년치를 한 번에 채우는 백필을 그 사람에게만 돌릴 수 있습니다.

운영 절차는 [OPERATIONS.md](OPERATIONS.md)에, 검색식 문법과 설치는 [README](../README.md)에 있습니다.
